Module 0 · Core Orientation — Navigation, Not Fate

0.1 · The Messy Block (Working Model)

Time is treated as layered and recursive rather than linear. Symbols mark resonance windows, not events. The Woven Map reads pressure, not future facts. Agency stays primary; symbolism never overrides choice.

0.2 · Astrology as Diagnostic Map

A chart functions like a compass, not a cause. It mirrors latent themes, tensions, and thresholds—never outcomes. Natal placements point to architecture and bias, not fixed traits.

0.3 · Pings & Recognition (SST Gate)

A ping is a lived recognition that a symbolic pattern matches experience. Nothing counts without ping. When logged, outcomes fall under SST:
	•	WB (Within Boundary) — clear resonance
	•	ABE (At Boundary Edge) — partial, inverted, or off-tone
	•	OSR (Outside Symbolic Range) — no resonance; valid null

0.4 · Map ≠ Mandate

Charts illuminate potential; they do not enforce outcomes. Transits highlight pressure; you decide movement. Language remains conditional.

0.5 · No Fixed Traits

Configurations (e.g., Sun/Moon/ASC) map tension pathways, not identities. Internal contradictions indicate structure, not pathology.

0.6 · Synastry as Resonance Map

Relational work compares two systems for tension, harmony, and loops. Requires full data for both charts. All reading stays bi-directional until ping confirms otherwise.

0.7 · Scientific Humility

No causal claim is required. Validity rests on repeatable recognition and clean misses. Falsifiability is enforced via ping and the SST triad.

0.8 · Pattern & Pressure

Aspects reflect tensions of becoming. The Map names thresholds; the body and life confirm or deny them. Resonance is recorded only when felt.

Socratic / E-Prime Construction Protocol

(Ensure every line is testable, situated, and non-prescriptive.)

Method
	1.	Locate the felt core (emprime).
What looks most charged in the solo chart now? Is it corroborated by more than one pressure point (tight orbs, clear hooks)?
	2.	Check for echoes.
Does today’s tension repeat, challenge, or invert a pattern already in play?
	3.	Write the mirror in body-close language.
Keep it concrete and situational. Avoid vague labels.
	4.	End with one Socratic question.
Draw it directly from the active tension. Let it test reality rather than prescribe behavior.

Boundary example
	•	Don’t: “Today is for setting boundaries.”
	•	Do: “If you notice overextension with X, could naming a limit bring relief or reveal regret?”

Woven Map Diagnostic Resonance Protocol

(Lexicon v1.3 — possibility mapping, agency-first)

0 · Guardrails
	•	Navigation, not fate. Hypotheses describe windows in any field (personal, relational, creative, systemic).
	•	Pre-declaration. Field Triggers and scenario prompts exist before a window opens.
	•	No retrofits. Resonance outside declared triggers is logged for learning, not counted as a hit.
	•	Agency first. Symbols never compel outcomes.
	•	Falsifiability. Hits, partials, and nulls all carry weight.

1 · Core Lexicon (Possibility Mode)
	•	Diagnostic Probe: a resonance window (tight aspects) paired with pre-declared triggers + field.
	•	Field Trigger: observable event defined in advance.
	•	Null Event: window closes without trigger; logged.
	•	Symbolic Audit Summary: operator memo (geometry, triggers, baseline, risk).
	•	Agency State: Supported / Unsanctioned / Latent / Under Pressure.
	•	Coherence Spike: short surge that matches a pre-declared trigger.
	•	Pressure / Openness / Restriction: plain-weather bands.
	•	Risk Archetype: volatility potential (never prescriptive danger).
	•	Visibility: likelihood of public echo vs. quiet.
	•	WB / ABE / OSR: SST outcomes.

2 · Probe Lifecycle
	1.	Define Geometry (tight orbs; field/domain noted).
	2.	Pre-Declare Triggers (observable, field-specific).
	3.	Set Window (start/end; no logging until active).
	4.	Establish Baseline (expected trigger rate outside geometry).
	5.	Scenario Map (pick 2–3 adjectives; pose field-anchored prompts).
	6.	Guidance (optional, on request only) — conditional, scenario-based.
	7.	Monitor Window (log hit / partial / null).
	8.	Classify Outcome (WB/ABE/OSR) and summarize.
	9.	Iterate (use nulls and hits to refine future probes).
